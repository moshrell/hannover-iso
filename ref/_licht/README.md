# Свет и плавность анимации в карточках (ветка `lm/p_licht`)

Правки только в `studio.js` и `studio.css`. `core/iso.css`, `core/iso-core.js` и здания не тронуты (от движка ничего не нужно).

## Что было не так (причина рывков)

Измерение трассой (Chromium, CPU ×4): при включении света Ihme-Zentrum, NORD/LB, Neues Rathaus и т. д. главный поток занят на 50–65 %. Причины:

1. `applyLight` вешал на каждый из ~3000 элементов свою CSS-задержку `--d` и одним переключением класса запускал ~3000 переходов (fill/stroke/opacity). Все они «ждут» своей задержки по 6–8 с и пересчитываются каждый кадр (стиль ≈ 0,9 с и отрисовка ≈ 0,8 с на 9 с времени, плюс пики по 500–850 мс в момент переключения).
2. Сверху на каждое окно навешивалась ещё и анимация `wflick` (вторая анимация на тысячу окон). Её отключение одно давало +9…13 кадров/с.
3. Фильтр `wglow` и маска краёв на `.stage svg` проверены отдельно: вклад небольшой (≈ ±2 кадра/с), поэтому не трогал.
4. Новые материалы (`pl`, `kc`, `kz`, `kr`, `iron`, `glb`) не были в студийных правилах скорости и шли 1,84 с вместо 0,92 с (в два раза дольше и дольше «висят» активными).

## Что сделано

**Свет теперь ведёт JS, а не тысяча CSS-задержек.** Каждый элемент переключается в свой момент (`requestAnimationFrame`, очередь по времени), а мягкий переход делает обычная CSS-transition уже после этого. Одновременно ждут не тысячи переходов, а меняются только несколько десятков элементов за кадр.
- Целевые значения (fill/stroke/opacity в «ночь» и «свет») один раз читаются из таблицы стилей (`getComputedStyle`, пока переходы выключены), второго набора цветов нет, `core/iso.css` остаётся единственным источником. В список попадает любой элемент, у которого значение реально меняется, поэтому ничего не забывается при новых материалах.
- Ночное состояние заранее «заморожено» в `element.style` (через 120 мс после загрузки, пока ничего не видно), так что переключение классов на `svg` ничего сразу не перекрашивает. Классы `lit/win/crown/lamps` после первого включения остаются; выключение = каждый элемент по очереди получает ночное значение. Только `element.style` (CSP соблюдён, `style="…"` в разметке нет).
- Для зданий с очень большим числом элементов переходы короче: `--ts` = 1500 / число элементов (не меньше 0,45). Ihme-Zentrum ×0,52, Welfenschloss ×0,45, Neues Rathaus ×0,74, NORD/LB ×0,8, маленькие здания (HCC и др.) без изменений. Длительности в `studio.css` заданы через `calc(… * var(--ts, 1))`; материалы `pl/kc/kz/kr/iron/glb` приведены к студийной скорости.
- `wflick` (короткое мигание при включении) теперь только у ~30 % окон и запускается в момент их включения; `prefers-reduced-motion` и `&sofort` идут по быстрому пути без волн, мерцания и «дыхания».

**Выключение вместе с фасадом.** Окна теперь получают время от высоты, как стены (`OFF.flood0 + (1 − h) · OFF.sweep`, небольшой разброс `OFF.winJit`), то есть гаснут той же волной сверху вниз и одновременно с фасадом, а не на 2,4 единицы позже. Волну пришлось растянуть (`OFF.sweep` 2,6 → 4,2): иначе все ~3000 элементов гаснут за 1,4 с и на тяжёлых зданиях получаются просадки. Для окон, сложенных в один `<path>` на этаж/класс (Ihme-Zentrum), высота берётся по ограничивающему прямоугольнику группы, поэтому такая группа гаснет одним шагом.

**Живые окна.** Старое мерцание 14 окон убрано. Теперь в покое небольшая доля окон гаснет и снова зажигается: 2,2–2,9 % окон одновременно тёмные (замер: Ihme-Zentrum 2,2 %, NORD/LB 2,9 %, HCC 2,6 %). Способ работает и для окон в одном пути: над выбранным окном лежит маленький тёмный «двойник» (`<path class="wn off ov">`) с теми же координатами подпути (`d` разбивается по `M`), который плавно (1,6 с) появляется и исчезает; сам `<path>` окон не трогается. Двойник вставляется сразу после источника, поэтому порядок рисования и перекрытия сохраняются (переплёты `.mul` остаются сверху). Число узлов: добавка не больше 96 (потолок), по зданиям: NORD/LB до 57, Ihme-Zentrum до 77, HCC 5; у зданий с менее чем 8 светлыми окнами (например Beginenturm) мерцания нет. Узлы создаются лениво (в дерево попадают, когда окно впервые гаснет) и убираются при выключении света. У больших зданий один двойник закрывает 2–4 соседних окна (так выходит нужная доля при ограничении в 96 узлов). Окна, которые и так выключены (`.off`), не выбираются. Мерцание стартует, когда волна включения дошла до конца, и сразу останавливается при выключении.

## Проверки
- Конечное состояние после волны совпадает с `&sofort` (расхождение пикселей >24: 0,0–0,9 %, это тёмные «двойники» и дыхание короны/звёзд); после ночи вид тот же, что до включения.
- Быстрое переключение (выкл/вкл/выкл/вкл посреди волны) на пяти тяжёлых зданиях: ошибок нет, итоговое состояние верное.
- Все 28 карточек (`landmarks/meta/*.json`): загружаются без ошибок в консоли, включение/выключение отрабатывают.
- `prefers-reduced-motion`: свет без волн, без мерцания и без анимаций.
- Кадры хода включения и выключения: `ref/_licht/frames.mjs` (NORD/LB: окна загораются по этажам, затем фасад снизу вверх; выключение идёт одной волной сверху вниз).

## Что осталось / ограничения
- Окна внутри одного `<path>` (Ihme-Zentrum и ещё несколько зданий) включаются и выключаются группой (этаж × класс), пока модуль зданий не разобьёт их на мелкие пути; для мерцания это не мешает (двойники), но сама волна у них ступенчатая. Это вопрос зданий, не карточек.
- Классы `lit/win/crown/lamps` на `svg` остаются после первого включения, внешний вид ведут встроенные значения элементов. Если кто-то добавит в `core/iso.css` правило от этих классов на другое свойство, кроме `fill`, `stroke`, `opacity`, оно в карточке не будет возвращаться при выключении; тогда расширить `PROPS` в `studio.js`.
- Карта (`karte.js`) эту логику не использует и не менялась; если плавность на карте тоже нужна, тот же приём (расписание в JS вместо задержек CSS) можно перенести.
- Для сборщика: ничего пересобирать не нужно (плитки не затронуты), достаточно слить `studio.js`/`studio.css` и выложить через `tools/sync-vorschau.sh`.
