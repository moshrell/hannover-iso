# Работа над картой в нескольких чатах

Идея: **один чат = одно здание**, один «сборщик» (главный чат) собирает всё вместе. Чаты не мешают друг другу, потому что каждый правит только свои файлы.

## Правила для чата-здания
- Берёт ровно одно здание. Ветка git: `lm/<имя>` (создать от `main`, пушить в неё, в `main` не пушить).
- Правит **только**: `landmarks/<имя>.js`, `landmarks/meta/<имя>.json`, `ref/<имя>/`.
  Нельзя: `landmarks/all.js`, `landmarks/meta.js`, `data/mitte.js`, `tiles/`, `README.md`, `karte.*`, `studio.*`, `core/*` (общий движок — если нужен новый материал/функция, написать об этом в конце работы, сборщик добавит).
- Новое здание: `python3 tools/new-landmark.py <имя> "<Заголовок>" <osm-id,…|lat,lon,кант> [высота]`.
- Старое здание (в `mitte.js`/`mitte2.js`/`altstadt.js`): сначала вырезать его модуль в свой файл `landmarks/<имя>.js` и удалить из старого файла (одним коммитом), затем дорабатывать.
- Материал: основной источник — **видео Google Earth** и фото на компьютере Степана `D:\Webdesign\hannover-iso\_fotos\<имя>\`; агент режет видео на кадры (`tools/frames.sh`), кладёт отобранные кадры в `ref/<имя>/foto/` и ведёт `ref/<имя>/INDEX.md` — полный порядок в **`prompts/VIDEO-ARBEIT.md`**. Видео в Git не кладём. Только внешний вид, интерьеры и открытки не использовать; в `ref/<имя>/README.md` таблица сторона→кадры→пригодно. Докачка недостающих сторон: `python3 tools/ref-dl.py "поиск" ref/<имя>/ansicht 6` (Wikimedia Commons; рисуем свои рисунки, копировать фото/логотипы нельзя). Поиск контура: `python3 tools/osm-find.py "<название>"`.
- Ориентация на карте: поле `face` в meta (`["street",[0,1],"Улица"]` — лицевая сторона к улице; `["compass",[-1,0],[-1,0]]` — локальное направление на сторону света), иначе наименьший поворот. Длинная ось модуля (x) всегда ложится на длинную ось здания по OSM.
- **Координаты внутри стены (deco у `K.wall`/`K.box`)**: x идёт вдоль стены от L к R, а y — **вниз от верхней кромки стены** (y = 0 — карниз, y = высота стены — низ). Окно на высоте z над низом стены h: `y = h − z − высота_окна`. Если считать y снизу вверх, окна «повисают» над крышей (так было в старом коде Welfenschloss).
- Правило проекта: сначала правда (как в жизни, по фото), потом красота; ракурс один (вид с юго-востока), без вращения.

## Проверка перед отправкой (обязательно, по порядку)
1. `sh tools/setup-cloud.sh` (один раз за сессию: Playwright, тестовый сервер на порту 8770).
2. Карточка: `node tools/studio-shot.mjs <имя> 390 760` (телефон) и `… 1000 700` (ПК) → смотреть `/tmp/studio_<имя>.png`: здание целиком в кадре, ничего не вылезает, нет проколов геометрии/сортировки.
3. Карта: `sh tools/preview.sh <имя> 1.5` → `/tmp/map_<имя>.png`: сторона фасада как в жизни, здание стоит на своём месте, нет «приросших» кусков старых OSM-домов.
4. Заполнить `landmarks/meta/<имя>.json`: `title`, `fact` (одна строка для карточки под картой), `studio` (текст в окне), `minor` (true = маленькая точка, видна при приближении ≥ 0,8), `rank` (порядок в списке).
5. Коммит в ветку `lm/<имя>` (сообщение по-русски): `git add landmarks/<имя>.js landmarks/meta/<имя>.json ref/<имя>` — **не `git add -A`** (проверки меняют сгенерированные файлы, их коммитит только сборщик). Затем push. **Отчёт обязательно файлом** `ref/<имя>/README.md` (в той же ветке; сборщик читает только его): что сделано, что осталось/ограничения, какие факты не сверены, что нужно от движка (`core/`) или сборщика. Короткий отчёт в чате дублирует его.

## Для сборщика (главный чат)
1. `git fetch`; слить нужные ветки `lm/*` в `main` (конфликтов быть не должно: файлы разные).
2. `python3 tools/build-landmarks.py` → `cd data && python3 prep.py osm.json.gz mitte.js` → плитки: **точечно** `node tools/render-tiles.mjs --at lat,lon,радиус_м [--at …]` (только блоки вокруг изменённых зданий, результат вмешивается в `tiles/`; минуты вместо ~45 мин), полный `node tools/render-tiles.mjs` без `--at` — только если менялся общий стиль/движок (`core/`, `studio`-свет, цвета).
3. `sh tools/sync-vorschau.sh ../kravets-site`, коммит в kravets-site (по-русски, `git diff --stat` перед коммитом), push в `master` → https://kravets-webdesign.de/vorschau/karte-ksn0/ (деплой по FTP идёт десятки минут).
4. Обновить README (на месте, устаревшее убрать).

Здания раздаёт очередь: чату достаточно фразы «Зайди в репозиторий moshrell/hannover-iso (ветка main), прочитай prompts/START.md и выполни» — он сам берёт свободное здание (`python3 tools/queue.py claim`, ветка `lm/<id>` = занято), читает `prompts/<id>.md` и `prompts/VIDEO-ARBEIT.md`. Список и статусы: `prompts/QUEUE.md` (ставит сборщик). Здания вне зоны `core` в `data/bbox.json` (Telemax): сборщик перед рендером расширяет зону детальных плиток.

## Промпт для нового чата-здания
```
Зайди в репозиторий moshrell/hannover-iso (ветка main), прочитай prompts/START.md и выполни.
```
